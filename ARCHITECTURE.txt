============================================================
BACKEND ARCHITECTURE OVERVIEW
============================================================

TECH STACK
----------
- Runtime:    Node.js + TypeScript
- Framework:  Express.js
- Database:   Supabase (PostgreSQL)
- AI:         OpenAI GPT-4.1 (evaluation), GPT-4.1-mini (hints), Whisper (transcription)
- Auth:       None (device UUID passed as userId)


------------------------------------------------------------
DATABASE TABLES
------------------------------------------------------------

games
  id               TEXT  PRIMARY KEY
  status           TEXT  available | locked | premium
  level            INTEGER               -- game's difficulty tier (1, 2, 3...)
  genre            TEXT
  name             TEXT
  short_intro      TEXT
  puzzle_id        TEXT  → puzzles.id

puzzles
  id               TEXT  PRIMARY KEY
  title            TEXT
  content          TEXT                  -- scenario shown to player (汤面)
  full_answer      TEXT                  -- full solution (汤底)
  parts            TEXT[]                -- key solution ideas for AI scoring
  hint             TEXT                  -- static fallback hint

user_profiles
  user_id          TEXT  PRIMARY KEY
  level            INTEGER DEFAULT 1     -- user's current unlocked level

user_game_progress
  user_id          TEXT
  game_id          TEXT  → games.id
  completed        BOOLEAN DEFAULT FALSE
  PRIMARY KEY (user_id, game_id)


------------------------------------------------------------
DESIGN PRINCIPLES
------------------------------------------------------------

- Game       = universal static data, same for every user
- Puzzle     = immutable content, fetched only on the challenge screen
- Session    = in-memory only, lives during active gameplay, lost on restart
- Progress   = owned by user_game_progress, never stored on the Game entity
- User level = unlocks games; a user can only play games at their level or below


------------------------------------------------------------
SERVICE LAYER  (src/Service/)
------------------------------------------------------------

gameService.ts
  - getAllGames()            fetch full catalog ordered by level
  - getGameById(id)          fetch single game
  - createGame(game)         insert new game
  - updateGame(id, fields)   partial update (status, name, genre, etc.)

puzzleService.ts
  - getPuzzleFromDB(id)      fetch full puzzle content

userService.ts
  - getUserProfile(userId)         get or create user profile
  - markGameCompleted(userId, gameId)  record a completed game
  - checkAndLevelUp(userId)        level up if all games at current level done
  - getGamesForUser(userId)        catalog with per-user lock + completed state

gameSessionService.ts
  - startSession(sessionId, gameId, puzzleId, userId)
  - requireSession(sessionId)
  - recordSuccessfulAnswer(sessionId, answer)
      → evaluateAnswerForParts → marks completedPartIndexes in memory
  - getCompletion(sessionId)   returns 0.0–1.0 ratio

evaluationService.ts
  - evaluateAnswer(answer, puzzle)
      → GPT-4.1-mini: returns yes | no | not_sure | not_related
  - evaluateAnswerForParts(answer, parts, puzzleContent)
      → GPT-4.1: returns indexes of solved parts

hintService.ts
  - generateHint(puzzle, completedPartIndexes)
      → GPT-4.1-mini: context-aware hint, calibrated by progress
      → vague at low progress, targeted at high progress
      → never reveals solved parts or solution verbatim


------------------------------------------------------------
API ROUTES  (all prefixed /v1/)
------------------------------------------------------------

USERS
  GET  /users/:userId             user profile + current level
  GET  /users/:userId/games       catalog with per-user lock + completed state

GAMES (catalog — admin/universal)
  GET  /games                     all games ordered by level
  GET  /games/:id                 single game
  POST /games/add                 create a new game
  PATCH /games/:id                update game fields

PUZZLES
  GET  /puzzles/:id               full puzzle content (challenge screen)
  POST /puzzles/add               create a new puzzle

GAMEPLAY (session-based)
  POST /games/start               body: { gameId, userId }
                                  → looks up game → gets puzzleId → creates session
                                  → returns { sessionId }

  POST /games/evaluate            body: { sessionId, userAnswer }
                                  → AI grades answer
                                  → if "yes": marks parts, updates completion,
                                              marks game done if 100%, checks level-up
                                  → returns { evaluation, completion, leveledUp, newLevel }

  POST /games/transcribe          query: ?sessionId, body: audio (multipart)
                                  → Whisper transcribes audio
                                  → same evaluation + progress flow as /evaluate
                                  → returns { success, transcript, evaluation,
                                              completion, leveledUp, newLevel }

  POST /games/hint                body: { sessionId }
                                  → reads session + puzzle from DB
                                  → AI generates progress-aware hint
                                  → returns { hint }

UTILITY
  GET  /health                    sanity check → { status: "ok" }
  GET  /me                        requires auth → user profile from token


------------------------------------------------------------
GAMEPLAY FLOW
------------------------------------------------------------

1. App launch
   → generate/load device UUID as userId (stored locally on device)

2. Home screen
   → GET /v1/users/:userId/games   (catalog with lock + completed per user)
   → GET /v1/users/:userId         (display level badge)

3. User taps Play on a game
   → GET /v1/puzzles/:puzzleId     (load full puzzle content)
   → POST /v1/games/start          (create session → returns sessionId)

4. User submits answer (text or audio)
   → POST /v1/games/evaluate  OR  POST /v1/games/transcribe
       ├── AI evaluates: yes | no | not_sure | not_related
       ├── if "yes":
       │     evaluateAnswerForParts → which parts does this solve?
       │     mark parts in session memory
       │     recalculate completion (completedParts / totalParts)
       │     if completion == 1.0:
       │       mark game as completed in user_game_progress
       │       check if all games at user's level are done → level up
       └── return { evaluation, completion, leveledUp?, newLevel? }

5. User is stuck
   → POST /v1/games/hint
       → AI reads session state → generates contextual hint


------------------------------------------------------------
IN-MEMORY SESSION STRUCTURE
------------------------------------------------------------

GameSession {
  id                   string    session UUID
  gameId               string    which game is being played
  puzzleId             string    linked puzzle
  userId               string    device UUID
  completedPartIndexes number[]  which puzzle parts are solved so far
  createdAt            Date
}

Note: sessions are lost on server restart. Progress is only
persisted to DB when completion reaches 100%.
